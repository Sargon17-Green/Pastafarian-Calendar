# v151 — גזירת מילוני שמות משני קובצי מקור ייחוס נעולים

## הבעיה

v150 מפענח מחדש כל שורת פלט מקור, אך מילון השמות מוזן כפרופיל. חתימה על הפרופיל בתוך תוכנית הבדיקה אינה הוכחה שהמילון נובע בפועל מבתי המקור ההיסטוריים. שינוי עקבי של הפרופיל והחתימה עלול ליצור מראית עין של מיפוי קאנוני אמין.

## המימוש

מימוש: `soak/runner/soak_source_derived_names_v151.py`. המנגנון מצמצם במכוון את הרשאתו **לשני מקורות ייחוס היסטוריים בלבד** שכבר קיים להם Lock מפורט:

- `REF-41`: Python + Türkçe, commit `0e4e75886dea4f4c7e0b6e39cce79e1d66f046f4`, מקור `tests/normative_reference.py`.
- `REF-24`: JavaScript + Interlingue, commit `03ac0c7f4db3c35487993dd31982faa37dd3948e`, מקורות `tests/normative-reference.js` ו־`src/source-language-catalog.js`.

המנגנון מאמת את בתי קובץ הנעילה הקיים מול Git blob SHA-1 היסטורי `db03a1c5a367c252fb07ba74c78cb7b2948048d5`, ומשתמש בבדיקות SHA-256, Git blob SHA-1 ואורך ביתי הקיימות ב־`native_raw_pair_gate_v018.verify_locked_sources` כדי לאמת את שלושת קובצי המקור. רק לאחר אימות בתים מופקים מתוכם 17 שמות קציצות ו־47 שמות חודשים, באמצעות ניתוח AST של טבלת Python וביטוי המותאם למבנה קטלוג JavaScript הנעול.

הפרופילים מופקים אוטומטית מהמילונים שחולצו, ולא מהצהרה חיצונית. עבור תוכנית השוואה v2 נדרש שקומיט המקור, נתיב המקור, מזהה המנוע, SHA-256 של קובץ המקור הראשי, גיבוב מילון השמות ושם נקודת הכניסה יצביעו במדויק על אותם מקורות נעולים. רק אז מנגנון v150 משחזר את כל שורות הפלט הגולמי מול JSONL. פרופיל שנמסר מבחוץ רשאי להיבדק כהצהרת השוואה בלבד, ואינו רשאי להחליף את התוצאה שחולצה מהמקור.

## הגבלת טענת המקוריות

נעילת ביתי מקור + AST/קטלוג מאמתים ש־**הערכים שחולצו אכן הופיעו בקבצים ההיסטוריים**. הם אינם מוכיחים שהפונקציה המקורית משתמשת במילונים המסוימים בכל מסלול קוד, שלא קיימת עטיפה מקומית מחליפה, מי הריץ את התהליך בפועל, שהתוצאה הקלנדרית נכונה או שמדובר באלגוריתמים עצמאיים. בשלב הזה רק שתי תבניות מקור נתמכות; מנוע אחר חייב שער נגזר־מקור משלו ואינו מקבל PASS גורף.

## בדיקות ומבחן Real Source

התווספו 20 בדיקות Python סינתטיות: שינוי קוד Python נעול, שינוי קטלוג JavaScript, שינוי קובץ המנוע הנפרד, שינוי Lock, זיוף SHA/commit/source path/entrypoint, גיבוב מילון שגוי, פרופיל מזויף, שינוי חודש בפלט המקור לצד חישוב מחדש של גיבובים וקבלות, והבדל מספרי אמיתי שאסור לטשטש.

Workflow v151 כולל גם את 112 בדיקות v147–v150, כלומר **132 בדיקות Python מתוכננות**. בנוסף נדרש אימות אמיתי של שלושת קובצי המקור הנעולים: הורדה מ־GitHub Contents API בהפניה ישירה לקומיט ההיסטורי, בדיקת אורך, SHA-256 ו־Git blob, שחזור מקור־בלבד ללא `F(c,t)`, ואימות עדים בלשניים כגון Akrep / scorpion / pute.

**סטטוס v151 אינו מתקבל אלא לאחר תוצאת CI `completed/success`, הוכחת לוגים וארטיפקט ראיות.** תוצאת מבחן סינתטי או עצם יצירת Workflow אינה מספיקה.
