# v152 — ראיות סטטיות לקשר בין שמות המקור ובין נקודות יצירת הפלט

**מצב השלב:** מימוש QA ו־CI שהוגש לבדיקה. קבלה מותנית ב־completed/success.

## מדוע נדרש השלב

v151 הוכיח מתוך בתים נעולים את תוכן מילוני השמות בשני מקורות הייחוס ההיסטוריים: REF-41 Python+Türkçe ו־REF-24 JavaScript+Interlingue. אך הופעת שמות בתוך קוד המקור אינה מספיקה כדי להוכיח שפונקציית הפלט משתמשת דווקא בהם.

## המימוש

`soak/runner/soak_static_name_output_path_v152.py` משתמש בקבצים שכבר עברו SHA-256, Git blob SHA-1 ובדיקות הבתים של v151, ובודק את מבנה מסלולי השמות במקורות ההיסטוריים:

* **Python:** באמצעות AST מאומת שקיימים בדיוק `NormativeCalendar.calendar_date` ו־`calendar_date_ids`, ושהראשונה מחזירה `DateResult` מחמשת השדות בסדר המקורי, כולל חיפוש שמות באמצעות `FROZEN_CUTLET_NAMES[ids.cutlet_name_index - 1]` ו־`FROZEN_MONTH_NAMES[ids.month_name_index - 1]`. בדיקת AST דוחה שינוי מפתח, טבלה, היסט אינדקס, סדר שדות או הגדרת פונקציה כפולה.
* **JavaScript:** נבדק אתר ההחזרה `calendarDate`, לרבות העברת `chosenCutlet.nameIndex` ו־`monthNameIndex` ל־`textByCanonicalIndex` בסדר שדות מקורי, חיבור למודול הקטלוג ומימוש `rows[canonicalIndex - 1].text`. זו **בדיקת תבנית לקסיקלית** על בתים שננעלו במלואם, לא מנתח AST כללי של JavaScript.

המנגנון אינו מריץ את המקורות, אינו מייבא את הממיר, אינו מייצר תאריך, ואינו פותח מחדש את `STOP_NEW_NATIVE_SOAK_DISPATCH`.

## בדיקות ומגבלות

`soak/process_tests/test_soak_static_name_output_path_v152.py` מכיל 20 בדיקות סינתטיות של תבניות קוד תקינות ושינויים מכוונים — החלפת מקור לשם, שינוי סדר שדות, שינוי אינדקס, שכפול הגדרה, הסרת ייצוא, ביטול חיפוש שמות במילון וכו'. שער CI מריץ בנוסף את 132 הבדיקות שהתקבלו ב־v151 ואת בדיקות שלושת קובצי המקור הנעולים, ולבסוף בודק את נקודות החיבור על אותם מקורות ממש.

**חשוב:** ראיית הקשר הסטטית אינה מוכיחה שבזמן הריצה בוצע אותו מסלול קוד, שאין קוד המשנה את המבנה בזיכרון, שהפלט בפועל נוצר מהמקור, שהממיר נכון, או ששני ממירים עצמאיים. ההיקף מוגבל לשני מקורות נעולים בלבד. עבור שאר הממירים נדרשים מתאמי ניתוח וראיות מקור ייעודיים.
