## Two independent gates, prospective QA only
A. BYTE_BINDING: separate receipt bundle with exact JAR bytes (not a recreated JAR), receipt JSON and source/worker evidence archive. SHA256 computed directly over archived JAR bytes must equal producer pre-execution and post-execution SHA256 and each worker claim. Pin repository, branch, full source SHA, run ID, attempt, job ID, workflow path/blob SHA, evidence archive ID and independently retrieved provider digest. Record compiler ZIP digest (measured, not a preapproved hash), version, compile argv, sorted source path/digest manifest, JAR byte length. Independent reader retrieves artifact metadata from GitHub API, checks run/job completion and exact identity, downloads bytes and compares SHA256 to provider digest. Never put an archive's own digest inside itself; bind separate artifact IDs/digests in an external readback receipt. Reject duplicate JSON keys, unknown schema, duplicate ZIP names, traversal, symlinks, missing files and oversized files; stream SHA256, no extraction or execution. Bounds: JAR 1..64 MiB, evidence ZIP <= 8 MiB, receipt <= 256 KiB, <= 128 entries, 120 s offline verifier; 64 MiB aggregate uncompressed JAR budget (adjust only on observed actual size before implementation). A coherent re-sign is not a trusted provider identity. A PASS proves byte correspondence under the pinned artifact and CI trust assumptions, not that arbitrary code was executed or reproducibly built.

B. CI_PROCESS_OBSERVATION: prospective Linux hosted-runner QA, independently captured kernel-derived process events from an explicitly separate observer (e.g. strace -f with execve/clone/fork/vfork/exit tracing, or kernel audit with documented permissions), not worker JSON or Python PIDs alone. Capture only scoped QA process tree; never environment, credentials or unrelated processes. Record boot/session identity, observer version, run/job/attempt, executable identity, parent/child relation, monotonic lifecycle ordering, argv fingerprint and exit status. Require exactly three successful Java exec lifetimes descended from three separate worker invocations, matching the bounded bridge command and pinned JAR path/digest; no unmatched Java exec or reuse of a lifecycle identity. A PID can be recycled: pair with creation event/session, require three nonoverlapping worker and JVM lifetimes and observed exit zero. Capture starts before the first worker and ends after the third; missing/truncated trace, unsupported observer or ambiguous identity => NOT_ASSESSED, never PASS. Independent parser must use raw capture, not producer-supplied summary; require original 99 rows and 495/1680 counts unchanged when a future authorized producer gate is exercised. Trust assumption: hosted CI platform, selected workflow and observer are trusted; even a kernel trace archived by that runner is not hardware or externally signed OS attestation. Report OS_ATTESTATION=false unconditionally. A/B gates may pass independently; do not promote missing evidence to failure of the calendar.
