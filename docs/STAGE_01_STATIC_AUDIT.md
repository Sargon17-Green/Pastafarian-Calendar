# 第 1 阶段静态审查

## 审查范围

本审查只覆盖当前 COBOL + 简体中文实现线的第 1 阶段。没有读取或比较其他实现的代码、测试、输出、散列或生成物，也没有加入第 2 至第 53 阶段的历史缺陷或补丁。

当前源树包含生产引导骨架、冻结的 `SourceLanguageCatalog`、本地任意精度整数服务、从嵌入式规范参考独立重写的测试 oracle，以及针对整数、基础计数、目录、选择和小型组合族的测试。

## 已完成的静态核对

1. 当前树共有 25 个 `PROGRAM-ID` 单元；所有已发现的静态 `CALL` 目标都在本树中有对应程序。
2. 已逐项核对主要跨程序接口的参数数量，并修正了按引用传递时发现的字段表示不一致，包括名称反排名的主目录计数和月份长度组合的总长度。
3. 规范日、闸门索引、闸门日和年份编号使用动态任意精度整数表示；只有规范本身有明确小上界的量继续使用普通整数字段。
4. 任意精度整数解析保留所有九位块，然后只在最高有效端规范化零块；这避免了 `1000000000` 被错误解析为 `1`。普通乘法的结果符号直接来自本次两个操作数。
5. `SAVE` 使用正除数的欧几里得余数实现，并包含 `M`、`M+1`、`2M` 等边界测试源代码。
6. 规范酱汁的 46 滴流程保留同一滴内的旧碗快照；每个碗先构造完整的 `s`，再计算 `s^2`，最后加入 `5*prev*next + i*position`。十二次后续搅拌同样先构造完整 `s` 再平方。
7. 第 46 滴的碗顺序独立保存，查询下一碗使用该顺序；后续十二次搅拌不会改写该顺序。
8. 短选择在同一答案环上执行拒绝；宽选择只构造一次宽整数，拒绝后在同一宽空间中按方向逐一移动，不重新采集数字。
9. 闸门服务使用任意精度索引和日期，并按正、负索引分别扩展。年份搜索采用 `(open, close]` 归属规则，年份上限为 5778，并从 5000 年逐年向前或向后移动。
10. 肉饼名称和月份名称的规范选择只使用 `canonicalIndex`；简体中文字符串只在最终展示层解析。
11. 月份编织使用规范状态 `remaining/openedUpTo/closedUpTo` 的精确计数与词典序反排名；小型 `[2,2]` 情形另有完整穷举测试源代码。
12. 有界组合和肉饼分割另有小型完整穷举测试源代码，用来核对 DP 的计数和词典序反排名，而不是让 DP 自证。
13. 对 `src/` 的静态检查没有发现第 01 至 26 个未来历史补丁的专用 legacy、detour、latch、late-filter 或兼容开关。当前只有规范允许的中性基础上下文、调度器、验证器、错误边界和指标外壳。
14. 未发现浮点规范计算、随机数、墙钟输入或依赖无序集合遍历来决定规范结果的路径。

## 审查中发现并已修正的问题

- 任意精度解析曾遗漏低位零块。
- 任意精度普通乘法曾从无关的除法符号暂存字段取得结果符号。
- 两处碗更新曾对错误的部分和求平方，而不是对完整 `s` 求平方。
- 碗排列的秩曾有 `drop-1` 的边界偏移错误。
- 两处 COBOL `CONTINUE` 曾被误当成其他语言的“跳到下一轮”；现已改为显式条件保护。
- 月份编织 DP 曾使用错误的循环索引。
- 名称计数和月份组合总长度曾存在按引用传递的字段表示不一致。
- 编织 memo 的重置曾只丢弃表头；现在会释放上一轮 memo 节点及其计数整数。

## 当前无法在本环境证明的事项

当前执行环境没有 `cobc` 或 `cobcrun`，且无法通过本环境的网络解析下载 GnuCOBOL。因此这里不能证明：

- 源码能够由目标 GnuCOBOL 版本完整编译；
- 所有 `CALL ... USING` 在真实 ABI 下均按预期工作；
- 测试实际运行通过；
- 完整日历 oracle 在大输入上的时间和内存行为满足实际运行要求。

此外，测试 oracle 仍有明确的堆所有权限制：部分 DP 表和许多短期 BigInt 结果采用进程生命周期所有权，重复的大型 oracle 调用可能造成堆持续增长。该问题目前未被证明会改变规范值，但它意味着不能把可靠性/所有权审查标记为完成。

## 工作序列的来源合规限制

本第 1 阶段工作序列早先已经使用过非 COBOL 运行时来编辑或检查文件。按照任务中的严格来源规则，这一事实不能在事后撤销。因此本目录可以作为“当前能够完成的最大静态 handoff”，但不能诚实地声明本工作序列满足 `foreign_language_runtime_called=NO`。

如果要求形式上完全符合该来源规则，必须在受控环境中从零重新执行第 1 阶段，并保证算法、测试、fixture 生成和相关计算全部只由 COBOL 完成。

### 8. 年 5000 候选数组容量证明

锚定年候选必须跨越计算日，并且候选长度最多为 5778 天。因此开门只能位于 `[计算日-5778, 计算日)`，关门只能位于 `[计算日, 计算日+5778]`。门间距至少为 42 天。即使对每一侧采用保守上界 139 个门，跨侧门对最多为 `139 × 139 = 19321`，严格小于候选数组容量 40000。因此该固定容量不会截断任何合法的年 5000 候选；它只是已证明安全的有限工作缓冲区，不是近似。
