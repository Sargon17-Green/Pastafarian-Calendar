# ಹಂತ 1 ಅರ್ಥಾತ್ಮಕ ಸ್ಥಿತಿ ಮಾಲೀಕತ್ವ ಪರಿಶೀಲನೆ

ಹಂತ 1ರ ಸ್ಥಿತಿ ಮಾಲೀಕತ್ವವನ್ನು ಮೂಲಸಂಕೇತ ಮಟ್ಟದಲ್ಲಿ ಸಂಪೂರ್ಣವಾಗಿ ಮರುಪರಿಶೀಲಿಸಲಾಗಿದೆ.

## ಜಾಗತಿಕ ಸ್ಥಿತಿ

`src/` ಮತ್ತು `test/` ಒಳಗೆ ಯಾವುದೇ `global` ಘೋಷಣೆ ಉಳಿದಿಲ್ಲ. ನಿಯಮಾತ್ಮಕ ಸ್ಥಿರಾಂಕಗಳು ಜಾಗತಿಕವಾಗಿ ಬದಲಾಗುವ ಮೌಲ್ಯಗಳಾಗಿ ಸಂಗ್ರಹವಾಗುವುದಿಲ್ಲ; ಅವು ಶುದ್ಧ procedures ಮೂಲಕ ದೊರೆಯುತ್ತವೆ.

ಹಿಂದಿನ ನಿಯಮಾತ್ಮಕ ಮಾದರಿಯಲ್ಲಿ ಹಂಚಿಕೊಂಡಿದ್ದ gate ಸಂಗ್ರಹವನ್ನು ತೆಗೆದುಹಾಕಲಾಗಿದೆ. ಈಗ ಪ್ರತಿ ಪೂರ್ಣ ದಿನಾಂಕ ಗಣನೆಗೆ ಹೊಸ `OracleCalendarState` ಸೃಷ್ಟಿಯಾಗುತ್ತದೆ. ಅದರ gate table, ಕನಿಷ್ಠ gate index ಮತ್ತು ಗರಿಷ್ಠ gate index ಆ ಗಣನೆಗೆ ಮಾತ್ರ ಸೇರಿವೆ.

stone table ಕೂಡ ಹಂಚಿಕೊಳ್ಳುವುದಿಲ್ಲ. ಪ್ರತಿ sauce ಗಣನೆ ತನ್ನ stone table ಅನ್ನು ಸ್ಥಳೀಯವಾಗಿ ನಿರ್ಮಿಸುತ್ತದೆ. ಸಂಯೋಜನಾ ಮತ್ತು weaving memo tables ಕೂಡ ಪ್ರತಿಯೊಂದು procedure ಆಹ್ವಾನದ ಒಳಗೆ ಸ್ಥಳೀಯವಾಗಿವೆ.

## ಬದಲಾಗುವ records, tables, lists ಮತ್ತು sets

`BaseMonsterContext` ಮತ್ತು `BaseDispatcher` ಪ್ರತಿ ಆಹ್ವಾನಕ್ಕೆ ಹೊಸದಾಗಿ ಸೃಷ್ಟಿಯಾಗುತ್ತವೆ. ಅವುಗಳ metrics table, logs list, diagnostics list ಮತ್ತು validation-failure list ಬೇರೆ ಸಂದರ್ಭದ ಜೊತೆ ಹಂಚಿಕೊಳ್ಳುವುದಿಲ್ಲ.

ಅರ್ಥಾತ್ಮಕ ಸ್ಥಿತಿಚಿತ್ರ ವ್ಯವಸ್ಥೆ ಮೇಲ್ಮಟ್ಟದ ಉಲ್ಲೇಖ ಹಂಚಿಕೆಯನ್ನು ಬಳಸುವುದಿಲ್ಲ. `baseCloneOwned` lists ಅನ್ನು ಪುನರಾವರ್ತಿಯಾಗಿ ನಕಲಿಸುತ್ತದೆ; table values ಅನ್ನು ಪುನರಾವರ್ತಿಯಾಗಿ ನಕಲಿಸುತ್ತದೆ; table keys ಅನ್ನು ಬದಲಾಗದ scalar ಮೌಲ್ಯಗಳಿಗೆ ಮಾತ್ರ ಸೀಮಿತಗೊಳಿಸುತ್ತದೆ. table ಯ default value ಕೂಡ ಬದಲಾಗದ scalar ಆಗಿರಬೇಕು. cyclic list/table references ಇದ್ದರೆ `seen` table ಮೂಲಕ ಒಂದೇ ಗಣನೆಯೊಳಗಿನ ಗುರುತು ಸಂಬಂಧವನ್ನು ಕಾಪಾಡಲಾಗುತ್ತದೆ.

sets ಗಾಗಿ ಸ್ಥಿತಿಚಿತ್ರ ನಕಲು ಬೆಂಬಲ ಇದೆ, ಆದರೆ ಬದಲಾಗುವ set members ಅನ್ನು ನಿರಾಕರಿಸಲಾಗುತ್ತದೆ. ಈ ಹಂತದ ಅರ್ಥಾತ್ಮಕ production ಅಥವಾ oracle ಸ್ಥಿತಿಯಲ್ಲಿ set ಬಳಕೆ ಇಲ್ಲ.

records ಸ್ವತಃ ಹಂಚಿಕೊಂಡ ಅರ್ಥಾತ್ಮಕ ಸ್ಥಿತಿಚಿತ್ರವಾಗಿ ಬಳಸಲಾಗುವುದಿಲ್ಲ. ಪ್ರಸ್ತುತ records ಪ್ರತಿಯೊಂದು ಆಹ್ವಾನಕ್ಕೆ ಸ್ಥಳೀಯವಾಗಿ ನಿರ್ಮಿಸಲ್ಪಡುತ್ತವೆ. ಬೆಂಬಲಿಸದ ಬದಲಾಗುವ ರಚನೆಯನ್ನು ಸ್ಥಿತಿಚಿತ್ರಕ್ಕೆ ನೀಡಿದರೆ ಮೌನ ಉಲ್ಲೇಖ ಹಂಚಿಕೆಯ ಬದಲು ಸ್ಪಷ್ಟ ಯಂತ್ರ ದೋಷ ಉಂಟಾಗುತ್ತದೆ.

## `SourceLanguageCatalog`

`buildSourceLanguageCatalog` ಪ್ರತಿಯೊಂದು ಕರೆಯಲ್ಲೂ ಹೊಸ catalog record ಮತ್ತು ಹೊಸ cutlet/month lists ಅನ್ನು ನಿರ್ಮಿಸುತ್ತದೆ. catalog ಮೂಲದ ಕನ್ನಡ ಮೌಲ್ಯಗಳು ಸ್ಥಿರ procedures ನಲ್ಲಿ ನಿರ್ಧಾರಗೊಂಡಿವೆ.

`validateSourceLanguageCatalog` ಆವೃತ್ತಿ, ಹಿಮಗಟ್ಟಿದ ಗುರುತು, 17+47 ಉದ್ದಗಳು, ಪ್ರತಿಯೊಂದು `canonicalIndex` ಮತ್ತು ಪ್ರತಿಯೊಂದು ಕನ್ನಡ ಮೂಲಪಠ್ಯವನ್ನು ಪರಿಶೀಲಿಸುತ್ತದೆ. ಒಂದು catalog ನಕಲಿನಲ್ಲಿ ಬದಲಾವಣೆ ಮಾಡಿದರೆ ಆ ನಕಲಿನ ಮಾನ್ಯತೆ ವಿಫಲವಾಗುತ್ತದೆ; ಹೊಸ catalog ನಕಲು ಅದರ ಪರಿಣಾಮಕ್ಕೆ ಒಳಪಡುವುದಿಲ್ಲ.

## generator ಮತ್ತು co-expression ಸ್ಥಿತಿ

ಯಾವುದೇ ಬಳಕೆದಾರ-ನಿರ್ಮಿತ generator procedure (`suspend`) ಇಲ್ಲ. `create`, `thread`, `spawn` ಅಥವಾ `co-expression` ಆಧಾರಿತ ಹಂಚಿಕೊಂಡ ಕಾರ್ಯಗತ ಸ್ಥಿತಿ ಇಲ್ಲ.

`key(table)` ಮತ್ತು `!set` ಅನ್ನು ಸ್ಥಿತಿಚಿತ್ರ ನಕಲಿನ ಒಳಗೆ ಸ್ಥಳೀಯ ಪುನರಾವರ್ತನೆಗೆ ಮಾತ್ರ ಬಳಸಲಾಗುತ್ತದೆ. ಅವು procedure ಹೊರಗೆ ಉಳಿಯುವ generator ಸ್ಥಿತಿಯನ್ನು ಸಂಗ್ರಹಿಸುವುದಿಲ್ಲ.

ಅರ್ಥಾತ್ಮಕ ಸ್ಥಿತಿಚಿತ್ರಕ್ಕೆ `co-expression` ನೀಡುವುದನ್ನು `baseCloneOwned` ಸ್ಪಷ್ಟವಾಗಿ ನಿರಾಕರಿಸುತ್ತದೆ.

## ಪರೀಕ್ಷಾ ಸ್ಥಿತಿ

ಹಿಂದಿನ `TEST_FAILURES` ಜಾಗತಿಕ ಮೌಲ್ಯ ತೆಗೆದುಹಾಕಲಾಗಿದೆ. ಈಗ ಪ್ರತಿಯೊಂದು ಪರೀಕ್ಷಾ ಚಾಲನೆಗೆ ಹೊಸ `TestState` record ಸೃಷ್ಟಿಯಾಗುತ್ತದೆ ಮತ್ತು assertion procedures ಅದನ್ನು ಸ್ಪಷ್ಟ argument ಆಗಿ ಸ್ವೀಕರಿಸುತ್ತವೆ.

## ವಿಫಲತೆ, ಹಿಂತಿರುಗಿಸುವಿಕೆ ಮತ್ತು ಮರುಪ್ರಯತ್ನ

ವ್ಯವಹಾರಾತ್ಮಕ ಸ್ಥಿತಿಚಿತ್ರ ಆರಂಭವಾದಾಗ ಹಿಂದಿನ ಅಂಗೀಕೃತ ಸ್ಥಿತಿ ಮತ್ತು ಹೊಸ ಬಾಕಿ ಸ್ಥಿತಿ ಸ್ವತಂತ್ರ ಸ್ವಾಮ್ಯ ಹೊಂದಿದ ನಕಲುಗಳಾಗುತ್ತವೆ. ತಪ್ಪು validator code ಅಂಗೀಕಾರವಾಗುವುದಿಲ್ಲ; ವ್ಯವಹಾರ ಸಕ್ರಿಯವಾಗಿಯೇ ಉಳಿದು ನಿಖರ ಹಿಂತಿರುಗಿಸುವಿಕೆಗೆ ಅವಕಾಶ ಕೊಡುತ್ತದೆ. ಹಿಂತಿರುಗಿಸುವಿಕೆ ಹಿಂದಿನ ಅಂಗೀಕೃತ ಸ್ಥಿತಿಯನ್ನು ನಿಖರವಾಗಿ ಮರುಸ್ಥಾಪಿಸುತ್ತದೆ. ಅದೇ ಒಳೀಡಿನ ನಂತರದ ಮರುಪ್ರಯತ್ನ ಹೊಸ ಸ್ಥಿತಿಚಿತ್ರದಿಂದ ಆರಂಭಿಸಿ ಸರಿಯಾದ ಮಾನ್ಯತೆ ನಂತರ ಮಾತ್ರ ಅಂಗೀಕರಿಸುತ್ತದೆ.

ಹಂತ 1ರ ಪರೀಕ್ಷೆಗಳು ಈ ಪ್ರತ್ಯೇಕತೆಗಳನ್ನು ಒಳಗೊಂಡಿವೆ:

- ಎರಡು ಸಂದರ್ಭಗಳ metrics, logs ಮತ್ತು dispatcher history ಪರಸ್ಪರ ಹಂಚಿಕೊಳ್ಳುವುದಿಲ್ಲ;
- ಒಳಸೇರಿದ lists ಮತ್ತು table values ಅಂಗೀಕಾರದ ನಂತರ ಕರೆಯುವ ಭಾಗದ ಬದಲಾವಣೆಯಿಂದ ಬದಲಾಗುವುದಿಲ್ಲ;
- ವಿಫಲ ಮಾನ್ಯತೆ ನಂತರ ಹಿಂತಿರುಗಿಸುವಿಕೆ ಹಿಂದಿನ ಸ್ಥಿತಿಯನ್ನು ಮರುಸ್ಥಾಪಿಸುತ್ತದೆ;
- ಮರುಪ್ರಯತ್ನದ ಸರಿಯಾದ ಮಾನ್ಯತೆ ನಂತರ ಮಾತ್ರ ಹೊಸ ಸ್ಥಿತಿ ಅಂಗೀಕರಿಸುತ್ತದೆ;
- ಇನ್ನೊಂದು ಸಂದರ್ಭದ ಅರ್ಥಾತ್ಮಕ ಸ್ಥಿತಿ ಬದಲಾಗುವುದಿಲ್ಲ;
- ಎರಡು `OracleCalendarState` ಗಳ gate tables ಹಂಚಿಕೊಳ್ಳುವುದಿಲ್ಲ;
- sauce ಕರೆಯ ಕ್ರಮವನ್ನು ಬದಲಿಸಿದರೂ ಅದೇ ಒಳೀಡಿಗೆ ಅದೇ ಫಲಿತಾಂಶ ಬರುತ್ತದೆ;
- ಹಿಂದಿನ sauce return object ಅನ್ನು ಬದಲಿಸಿದರೂ ಮುಂದಿನ sauce call ಫಲಿತಾಂಶ ಬದಲಾಗುವುದಿಲ್ಲ;
- ಒಂದು catalog ನಕಲಿನ ಬದಲಾವಣೆ ಮತ್ತೊಂದು ಹೊಸ catalog ನಕಲಿಗೆ ಹರಡುವುದಿಲ್ಲ.

## ತೀರ್ಮಾನ

ಹಂತ 1ರ ಅರ್ಥಾತ್ಮಕ ಸ್ಥಿತಿ ಮಾಲೀಕತ್ವ ಪ್ರತಿ ಆಹ್ವಾನ ಅಥವಾ ವ್ಯವಹಾರಕ್ಕೆ ಸ್ಪಷ್ಟವಾಗಿದೆ. ಹಂಚಿಕೊಂಡ ಬದಲಾಗುವ ಅರ್ಥಾತ್ಮಕ ಜಾಗತಿಕ ಸ್ಥಿತಿ ಉಳಿದಿಲ್ಲ. ವೀಕ್ಷಣಾ ಸ್ಥಿತಿ ಪ್ರತಿ ಸಂದರ್ಭಕ್ಕೆ ಸೇರಿದೆ ಮತ್ತು ನಿಯಮಾತ್ಮಕ ಮಾದರಿ ಅದನ್ನು ಓದುತ್ತಿಲ್ಲ.

ಮೂಲ Unicon ಸಂಕಲನ ಮತ್ತು ಪರೀಕ್ಷೆಗಳು ಇನ್ನೂ ಈ ಪರಿಸರದಲ್ಲಿ ನಡೆಯಿಲ್ಲ. ಆದ್ದರಿಂದ ಸ್ಥಿತಿ ಮಾಲೀಕತ್ವ ವಿನ್ಯಾಸ ಮತ್ತು ಪರೀಕ್ಷಾ ವ್ಯಾಪ್ತಿ ಪೂರ್ಣಗೊಂಡಿವೆ; ಕಾರ್ಯಗತ ಪರಿಶೀಲನೆ ಮಾತ್ರ ಬಾಕಿಯಿದೆ.
