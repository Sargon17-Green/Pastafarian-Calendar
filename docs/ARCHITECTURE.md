# ಹಂತ 1 ವಾಸ್ತುಶಿಲ್ಪ

ಈ ಹಂತದಲ್ಲಿ ಮಹಾಕಾಯ ವಾಸ್ತುಶಿಲ್ಪವನ್ನು ಉದ್ದೇಶಪೂರ್ವಕವಾಗಿ ತಟಸ್ಥವಾಗಿ ಇಡಲಾಗಿದೆ. ಮುಂದಿನ ಹಂತಗಳಿಗೆ ಸೇರಿದ ಐತಿಹಾಸಿಕ ಗಾಯ, ಹಳೆಯ ದೋಷ, ಹೊಂದಾಣಿಕೆ ಗುರುತು ಅಥವಾ ತಿದ್ದುಪಡಿ ಹೊದಿಕೆಯನ್ನು ಈಗ ಸೇರಿಸಲಾಗಿಲ್ಲ.

`BaseMonsterContext` ಒಂದು ಆಹ್ವಾನಕ್ಕೆ ಮಾತ್ರ ಸೇರಿದ ಸ್ಥಿತಿಯನ್ನು ಹಿಡಿದಿಡುತ್ತದೆ. ಅದರೊಳಗೆ ಬದಲಾಗದ ಒಳೀಡು, ಜೀವನಚಕ್ರ ಸ್ಥಿತಿ, ಅರ್ಥಾತ್ಮಕ ಸ್ಥಿತಿಚಿತ್ರ, ಬಾಕಿ ಸ್ಥಿತಿಚಿತ್ರ, ಹಿಂತಿರುಗುವ ಸ್ಥಿತಿಚಿತ್ರ, ಮಾಪಕಗಳು, ದಾಖಲೆಗಳು, ನಿರ್ಣಯ ಸಹಾಯಕ ದತ್ತಾಂಶ ಮತ್ತು ನಿರ್ಣಾಯಕ ದೋಷಸ್ಥಿತಿ ಇವೆ.

ಅರ್ಥಾತ್ಮಕ ಸ್ಥಿತಿಗೆ ಮೂಲ ನಿಯಮ:

```text
snapshot -> pending -> validation -> commit
```

ಮೇಲಿನ ಸಾಲು ಯಂತ್ರಾತ್ಮಕ ಸ್ಥಿತಿಚಕ್ರ. ಮಾನ್ಯತೆ ಪರಿಶೀಲನೆ ವಿಫಲವಾದರೆ ಅಪೂರ್ಣ ಅರ್ಥಾತ್ಮಕ ಫಲಿತಾಂಶವನ್ನು ಹಿಂತಿರುಗಿಸಲಾಗುವುದಿಲ್ಲ. ಹಿಂತಿರುಗುವ ಕ್ರಿಯೆ ಕೊನೆಯಾಗಿ ಅಂಗೀಕರಿಸಿದ ಸ್ಥಿತಿಚಿತ್ರವನ್ನೇ ಮರುಸ್ಥಾಪಿಸಬೇಕು. ಸ್ಥಿತಿಚಿತ್ರ, ಬಾಕಿ ಮೌಲ್ಯ ಮತ್ತು ಹಿಂತಿರುಗುವ ಮೌಲ್ಯಗಳು ಒಳಸೇರಿದ ಬದಲಾಗುವ ರಚನೆಗಳಿಗೆ ಒಂದೇ ಉಲ್ಲೇಖವನ್ನು ಹಂಚಿಕೊಳ್ಳಬಾರದು; ಹಂತ 1ರ `baseCloneOwned` ಈ ಮಾಲೀಕತ್ವ ಗಡಿಯನ್ನು ಜಾರಿಗೆ ತರುತ್ತದೆ.

`BaseDispatcher` ಹಂತ ಮಾರ್ಗವಿನ್ಯಾಸಕ್ಕೆ ತಟಸ್ಥ ಕವಚ. `baseValidateIntegerDays` ಒಳೀಡು ಮಾಲೀಕತ್ವ ಮತ್ತು ಪ್ರಕಾರ ಗಡಿಯನ್ನು ಪರಿಶೀಲಿಸುತ್ತದೆ. `BaseMetrics` ಮತ್ತು ದಾಖಲೆಗಳು ವೀಕ್ಷಣೆಗೆ ಮಾತ್ರ; ಅವು ಅರ್ಥಾತ್ಮಕ ಒಳೀಡಾಗಬಾರದು.

`normative_oracle.icn` ಪ್ರತ್ಯೇಕ ಪರೀಕ್ಷಾ ಘಟಕ. ಕಾರ್ಯನಿರ್ವಹಣಾ ಆರಂಭಿಕ ಭಾಗ ಅದನ್ನು ಕರೆಯುವುದಿಲ್ಲ ಮತ್ತು ವಿಫಲತೆಯ ಪರ್ಯಾಯ ಉತ್ತರವಾಗಿ ಬಳಸುವುದಿಲ್ಲ.


ನಿಯಮಾತ್ಮಕ ಮಾದರಿ ಯಾವುದೇ ಹಂಚಿಕೊಂಡ ಬದಲಾಗುವ ಜಾಗತಿಕ ಸ್ಥಿತಿಯನ್ನು ಹೊಂದುವುದಿಲ್ಲ. ಪ್ರತಿ ಪೂರ್ಣ ದಿನಾಂಕ ಗಣನೆ ತನ್ನದೇ `OracleCalendarState` gate table ಅನ್ನು ಹೊಂದುತ್ತದೆ; stone tables ಮತ್ತು DP memo tables ಪ್ರತಿ ಆಹ್ವಾನಕ್ಕೆ ಸ್ಥಳೀಯವಾಗಿವೆ. ಪರೀಕ್ಷಾ ಚಾಲಕವೂ ಜಾಗತಿಕ ವಿಫಲತೆ ಎಣಿಕೆಯನ್ನು ಬಳಸುವುದಿಲ್ಲ.

`co-expression`, ಬಳಕೆದಾರ-ನಿರ್ಮಿತ generator, thread ಅಥವಾ ಹಂಚಿಕೊಂಡ ಕಾರ್ಯಗತ ಸಂದರ್ಭ ಈ ಹಂತದಲ್ಲಿ ಇಲ್ಲ. ಅರ್ಥಾತ್ಮಕ ಸ್ಥಿತಿಚಿತ್ರಕ್ಕೆ `co-expression` ಅಥವಾ ಬೆಂಬಲಿಸದ ಬದಲಾಗುವ ರಚನೆ ಬಂದರೆ ಮೌನವಾಗಿ ಹಂಚಿಕೊಳ್ಳುವ ಬದಲು ಸ್ಪಷ್ಟ ಯಂತ್ರ ದೋಷ ಉಂಟಾಗುತ್ತದೆ.
