# COBOL 任意精度整数基础设施

规范整数没有固定上界。普通 GnuCOBOL 数值字段不能独立承担这一要求，因此本实现线在 第 1 阶段 建立自己的整数表示。

`BIG-INTEGER-SERVICE` 使用动态分配的双向链表。每个节点保存一个十进制九位块，基数为 `1000000000`。符号与块链分开保存；零使用符号 0 和空链。链表长度由可用内存决定，而不是由 `PIC` 中预先声明的规范位数决定。

服务提供：十进制解析、复制、有符号比较、加法、减法、乘法、带余除法、正除数的欧几里得余数以及十进制输出。所有这些操作都在 COBOL 源码中实现，不以浮点数、截断计数或外部语言库代替规范整数。

九位块保证单次块乘积小于 `10^18`；当前乘法临时字段可以精确保存该范围。长除法逐块建立余数，并以整数二分搜索求每个商块，不使用浮点估计。

生产输入和 oracle 的规范整数不得由日志、指标、分配地址或对象身份决定。服务本身提供 `FREE-A` 供明确释放动态整数。当前 第 1 阶段 测试 oracle 将大量短期 BigInt 分配视为测试进程生命周期资源；它尚未证明在超长重复 oracle 调用下可以保持有界堆占用。因此该点属于可靠性审查中的已知限制，而不是规范数值语义的替代路径。

第 1 阶段 的测试覆盖 39 位的 `M`、前导零、块边界 `1000000000`、跨块加法、正负乘法、带内部零块的除法、负数欧几里得余数以及规范 `SAVE` 边界。由于当前交付环境没有 `cobc`，这些测试在此环境中只能完成静态审查，不能声称已经执行通过。
