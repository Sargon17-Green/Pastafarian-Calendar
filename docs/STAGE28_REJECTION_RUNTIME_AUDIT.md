## የተገኘው ችግር

`old_wide_pick_high_first` ውስጥ ሲሆን `accepted > limit`፣ በእያንዳንዱ ዙር `accepted = 1 + regularMod(accepted - 1 + step, space)` ይፈጸማል። የተከለከለው ክልል `limit+1..space` ነው። ስለዚህ የሚጠበቀው የዙር ብዛት እጅግ ትልቅ ሊሆን ይችላል።

ለምሳሌ ትክክለኛ የግቤት ምስክር፦

- `M = 2^127 - 1`፣ `S = M^2`፣ `n = (S+1)/2` (integer)።
- `AnswerStream{ first: M, step: 1 }`። ሁለት አሃዞች ይመረጣሉ (`M < n <= M^2`)።
- `digit_0 = M-1`፣ `digit_1 = 0`።
- legacy high-first `raw = 1+(M-1)M = S-M+1`።
- `limit = floor(S/n)n = n`። `raw > limit`።
- ወደፊት `step=+1` ስለሆነ `raw` ከ `S` በኋላ `1` ይሆናል። እስከዚያ ድረስ ሁሉም እሴቶች ከ `limit` በላይ ናቸው።

**ትክክለኛ የrejection ዙሮች:** `S - raw + 1 = M = 170141183460469231731687303715884105727`። ይህ የተወሰነ ቁጥር ነው፣ ግን በተግባር ያልተገደበ የሩጫ ጊዜ አደጋ ነው።

ትክክለኛው little-first ህግ ላይ `raw = 1+(M-1)+0*M = M` ነው፤ `M <= n` ስለሆነ rejection አያስፈልግም። ይህ ምሳሌ የlegacy ልዩነትን እና የሩጫ ጊዜ አደጋን በአንድ ጊዜ ያሳያል።

## የዙር ብዛት ቀጥተኛ ሂሳብ

ለማንኛውም `1 <= x <= S`፣ `1 <= L < S` እና `x > L` ከሆነ፣ በአንድ-አንድ የሚሄድ ክብ ዑደት ትክክለኛው የrejection ብዛትና የመጨረሻው እሴት፦

| step | rejected_count | first accepted value |
| --- | --- | --- |
| +1 | `S-x+1` | `1` |
| -1 | `x-L` | `L` |

ማስረጃ፦ `x>L` ስለሆነ የተከለከለው ክልል ቀጣይ ነው። በ`+1` አቅጣጫ እስከ `S` እና ከዚያ `1` ይደርሳል፤ በ`-1` አቅጣጫ እስከ `L` ይወርዳል። ይህ በBigInt ሂሳብ ያለ ብዙ ዙር ሊሰላ ይችላል። **ይህ የማሻሻያ ሃሳብ እንጂ በዚህ ማስረጃ የተተገበረ ለውጥ አይደለም።**
