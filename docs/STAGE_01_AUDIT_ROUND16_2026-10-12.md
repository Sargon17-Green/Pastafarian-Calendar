# 第一階段第十六輪：不同呼叫順序、精確計數快取及回傳值的所有權

日期：2026-10-12；目標分支：`Perl+國語`。這仍是 Stage 1 的獨立計算器稽核，不代表正式曆法 API 已接線。禁止改動 `main`、語言目錄、Stage 2，也不保存任何使用者 `HANDOFF_*` 檔案。

## 緣由

第十五輪已修正直方圖接收器的 BigInt 別名問題；然而此前各測試大多只針對一種呼叫順序或個別月份前綴，未以**同一共享快取**跨多種月份分布、任意合法前綴、三種不同儲存引擎交錯呼叫。同時須確認公開函數回傳的 Math::BigInt 不會別名到快取內部的精確未來計數。

## 新增的回歸

`t/47_suffix_cache_call_order.t` 從每個月剩餘天數、首次開啟次序及末次關閉次序，獨立枚舉四種異質月份向量 `[2,2,2]`、`[1,2,2]`、`[3,1,2]`、`[2,1,2,1]` 的**全部合法部分前綴**（包括空前綴和完整前綴）。以倒序查詢前綴，並輪轉 `resident`、`stream` 和 `stream-indexed` 的先後順序。

對每個合法前綴，用 `countWeavingSuffixPolynomial` 獨立規範參考器取得精確結果，要求三種引擎都相等；然後刻意 `badd` 改寫每個引擎的回傳物件並重取相同前綴，要求計數仍保持不變。同時檢查輸入前綴不變、四種不同月份長度的索引物件均獨立存在、快取解除後臨時檔立即清理，以及 Math::BigInt 輸入月長及前綴並未因正規化而改寫。

以 32 KiB 的每檔資源預算執行小型語義樣本；測試不宣稱這一限制可滿足 252 日或 5,778 日的資源需要。

## 尚未關閉的限制

擬合測試的月份向量不等同於從規範年份構造流程抽取的真實月份序列。5,778 日上界的 RAM、磁碟與時限保證以及正式日期轉換 API 的整合仍未完成；`LAST_COMPLETED_STAGE=1` 仍只表示啟動階段既有狀態，不得誤報整個實作 final。
