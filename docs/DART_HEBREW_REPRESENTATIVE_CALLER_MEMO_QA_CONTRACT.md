Timing mode must disable trace allocations, serialization, extra oracle work and VM-service instrumentation; off runs the same wrapper bypass, additionally compare pristine source to off to quantify wrapper cost. Use freshly launched processes per arm/workload and 5 paired repeats alternating order (AB BA AB BA AB) for each lifecycle policy against off; record wall startup separately, calculate-only per-call and total monotonic elapsed microseconds, raw samples, paired gain 1-on/off, median of paired gains (not ratio of medians), positive count and control overhead on/off-1. Memory pass in separate processes with trace off; Dart ProcessInfo.currentRss/maxRss or OS peak RSS in bytes, sampled at baseline and each call/reset, report baseline-relative current RSS and absolute process peak. For actual managed heap use Dart VM service getMemoryUsage on same isolate (heapUsage, heapCapacity, externalUsage) at equivalent checkpoints; record SDK/service support and raw responses; if unavailable mark heap NOT_MEASURED, never substitute RSS/model. No forced GC in timed runs; optional diagnostic GC only in separate memory pass, compare identical policy off/on. RSS need not fall on clear (allocator retention); use heap/reset/model evidence separately. These are QA triage thresholds, not product memory requirements.
