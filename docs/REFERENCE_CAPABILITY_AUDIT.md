# การตรวจสิทธิ์อ้างอิงของ Pony ในระยะที่ 1

สถานะที่เปลี่ยนค่าได้ของคำขอหนึ่งครั้งอยู่ใน `MonsterContext ref` เท่านั้น ชนิด `ref` ใช้ได้ภายใน `actor` ที่ถือมันและไม่ใช่ชนิดที่ส่งข้าม `actor` ได้ จึงไม่มีทางส่งบริบทที่เปลี่ยนค่าได้ไปยัง `actor` อื่นโดยตรงผ่านระบบชนิดของ Pony

ค่าที่ต้องข้าม `actor` ถูกแยกเป็นสองชนิดที่อ่านอย่างเดียว `BigInt val` ใช้สำหรับจำนวนเต็มเชิงความหมาย และ `MonsterSnapshot val` ใช้สำหรับภาพสถานะเพื่อการตรวจสอบ ทั้งสองชนิดไม่มีฟิลด์ที่เปิดทางไปยัง อาร์เรย์ หรือ แมป ที่เปลี่ยนค่าได้ของคำขอ

การสร้างข้อความที่ต้องกลายเป็น `String val` ใช้ `recover val` เมื่อมีการสร้าง `String ref` แล้วเติมข้อมูลภายในบล็อกเดียว ข้อมูลจากภายนอกบล็อกที่ถูกอ่านมีเพียงค่าแบบส่งข้าม `actor` ได้ เช่น `String val`, `BigInt val` หรือ ค่าสเกลาร์ ไม่มีการยกสิทธิ์ของ การอ้างอิง ที่อาจมี alias แบบเขียนได้

`CatalogEntry` เป็น `class val` และรายการที่คืนจาก `SourceLanguageCatalog` เป็น อาร์เรย์ ใหม่ทุกครั้ง ผู้เรียกจึงแก้รายการของตนได้โดยไม่แก้ข้อมูลของการเรียกอื่น ส่วนออราเคิลเก็บ `NormativeGateStore` และ หน่วยจำผล ของการนับไว้ใน อินสแตนซ์ ของตนเอง ไม่มีตัวแปรส่วนกลางที่เปลี่ยนค่าได้

ตัวตรวจสอบของโครงเริ่มต้นตรวจว่า อาร์เรย์ ภายใน `MonsterContext` ไม่ใช่วัตถุเดียวกันก่อนเปลี่ยนสถานะเป็น `READY` การทดสอบอีกชุดสร้างบริบทสองตัวและตรวจว่า อาร์เรย์ กับ แมป ทุกตัวเป็นคนละวัตถุ จากนั้นแก้ค่าของตัวแรกและยืนยันว่าตัวที่สองไม่เปลี่ยน

การทดสอบขอบเขต `actor` ส่ง `MonsterSnapshot val` และ `BigInt val` ไปยัง `actor` ผู้รับโดยตรง การคอมไพล์ เนทีฟ จึงเป็นส่วนหนึ่งของหลักฐานว่า สิทธิ์อ้างอิง ของสองเส้นทางนี้สอดคล้องกับกฎการส่งข้อความของ Pony หากชนิดใดเผลอกลายเป็น `ref` การทดสอบดังกล่าวต้องคอมไพล์ไม่ผ่านแทนที่จะยอมให้แชร์สถานะที่เขียนได้

อายุของ `MonsterContext` ไม่ถูกยืดโดย manager, dispatcher, primitive, แคช หรือ ทะเบียน ใดในระยะที่ 1 เพราะไม่มีองค์ประกอบเหล่านี้เก็บ การอ้างอิง ของบริบทไว้ เมื่อผู้เรียกปล่อย การอ้างอิง สุดท้าย บริบทและ โครงเก็บข้อมูล ที่เป็นของมันจึงพร้อมให้ตัวเก็บขยะของ Pony จัดการพร้อมกัน
