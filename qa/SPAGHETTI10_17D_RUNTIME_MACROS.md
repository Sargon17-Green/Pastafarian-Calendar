## From isolated opcodes to genuinely composed runtime programs

QA10's independent source is
`010efd012ae52a60740aa97750b5a02519912e92`.
Instead of the five individually generated opcodes per axis in QA09,
it **generates a 13-byte executable program at each of sixteen
previously unvisited 17-dimensional source locations**: 208 newly
written executable instruction bytes in all. All 208 original
locations contain deceptive `@` instructions, overwritten with
native 17D `p` before the IP can enter them. Each emitted byte
also gets native 17D `g` readback emitted as numeric output.

For a healthy axis i, triangular accumulator `H=i(i+1)/2`,
previous 2D Native QA06 branch seed `s` and residues `A,B`:

```
r = (A - 31) + (B - 33)
m = 2 + ((H + s + r) mod 2)   # 2 or 3
Achar = '0' if (H+s+r) even else ':'
Dchar = ':' if (H+s+r) even else '0'
program = Achar + '$' + Dchar + '$' +
          chr(48+m) + '*' + chr(48+m) + '/' +
          ':' + '$' + ':' + '$' + '>'
```

The executable suffix is a true, stack-neutral subprogram:
`m*m/` multiplies the top accumulated value by the same
*history-determined* factor and divides it back; the two `:$`
pairs leave the stack unchanged. The last `>` itself is runtime
emitted and executes to route the IP east on the new hyperplane.
Unlike the earlier QA09 `0$>/:$>` fragments, the generated program
performs nontrivial work during the subsequent IP traversal. The
factor varies across axes and the input seed, and the cross-worker
residues are incorporated into **every** byte emitter.

A careful design review of the first twelve-byte idea found an
extra stack residue. The final design uses thirteen bytes, including
the restoring `:$` pair and generated `>`. Therefore the experimental
source has **208** emitted opcodes, not the originally estimated 192;
this is a deliberate correction to preserve real Native stack semantics.

The QA10 script requires eight full native executions across
two seeds, two scheduling modes and two repetitions each, with
exact 227-integer output (two worker residues, sixteen groups of
thirteen generated byte receipts and axis markers, plus checksum).
The expected future instruction sequence is checked byte-for-byte,
not just by final arithmetic parity. It additionally demands that
replacing all 208 original source traps with `q` preserve parity for
both seeds.

The 24 independent negative controls comprise four worker disruptions,
sixteen dimension contributions and four generated-instruction roles
(multiply, divide, stack drop and route turn). Bounded timeouts
demonstrate changed termination, not alternative terminated output.
Source pins, oracle provenance, masking and all negative controls must
pass before the QA10 status may change from provisional to accepted.

Important scope limit: an interpreter implementation is not a proof of
maximal complexity. This round demonstrably increases causal and
physical self-modification, but is still a QA sidecar and not a full
seventeen-dimensional implementation of the canonical Pastafarian
calendar algorithm.

The first exact-head [Native QA10 run 39065096851](https://github.com/Sargon17-Green/Pastafarian-Calendar/actions/runs/39065096851) passed the QA06→QA09 Native parent chain, including both worker shards, before QA10 seed1 exceeded its first 25-second bound (`rc=124`). The additional independent source generator `qa/stage1_spaghetti10_build.py`
verifies bit-for-bit reproducibility of the full 17D specimen SHA and

This rules out nonreproducible geometry, but does not execute Funge.

The minimal isolated Native IP-motion forensics source is
`qa/stage1_spaghetti10_ip_forensics.py`, run under an instrumented
**disposable copy** of the pinned Funge++ engine. It executes six
physical stage-stop fixtures as well as the complete program with a
longer bound, records `Z`, `@` and periodic IP positions, and
differentiates source arithmetic errors, control-flow mistakes and
large-performance costs. Diagnostic engine instrumentation is not
a modification to the Pastafarian Calendar production source and
does not count toward QA10 acceptance.

## Negative-control soundness upgrade (pending new Native rerun)

A second methodological audit found that a mutant timeout of 3 seconds
would be meaningless for a healthy QA10 source whose full execution
already exceeds 25 seconds. That earlier, uncalibrated test script
**must not** be used to claim causal nontermination. The repaired
harness measures all healthy source runs, sets a shared mutant budget to
`max(20, floor(1.5 * slowest_healthy_seconds)+5)` and executes a
physically **inert control mutation** at the unreachable 17th-dimensional
sentinel under the same bound. Any inert-control failure blocks all
causality claims. The third `$` opcode occurrence in a stage, rather
than the original QA09 prefix, is now chosen for the generated-macro
stack-drop negative control. All mutation results distinguish changed
output from a bounded nontermination event; no mutant timer shorter
than a healthy execution is accepted.

The SHA-pinned source reconstruction is also checked directly in the
full QA10 gate before the real Native interpreter starts QA10. The
historical first Native RED 39065096851, which timed out at 25 seconds
for seed 1 in `-fthreads=funge`, remains preserved; it is not evidence
of behavioral divergence by itself. The separate stage-bounded Native
forensic workflow checks whether the larger source merely needs more
time or has an actual wrong IP route. Until both the new timed gate
and independent forensic results support it, QA10 is **OPEN**.
